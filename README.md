# Wedding OS

> 결혼 준비가 조금 더 선명해지도록 돕는 우리 둘만의 결혼식 운영 시스템.
> 체크리스트·후보 풀·비교표·청첩장·RSVP까지 한 도메인에서.

Wedding OS는 결혼 준비를 처음 하는 커플이 할 일과 결정을 한 흐름 안에서 볼 수 있게 돕는 앱입니다. AI는 업체나 상품을 보장하지 않고, 후보·비교표·질문·문구 초안을 만들어 사용자가 직접 확인하고 결정할 수 있게 돕습니다.

---

## 네 가지 방법으로 시작할 수 있어요

### 🔗 1) 간편 시작 — 추천

운영자가 준비한 저장소를 쓰되, 결혼 준비 데이터는 **브라우저에서 암호화된 암호문**으로만 올라갑니다. 복구 링크를 배우자에게 보내 함께 편집하고, 기기를 바꿔도 이어서 쓸 수 있습니다.

장점: 별도 Supabase 셋업 없음 · 함께 편집 · 복구 링크
단점: 로그인 신원은 운영자가 알 수 있음. 암호문구를 잊으면 운영자도 복구할 수 없음

### 📱 2) 혼자 먼저 시작 — 가장 쉽고 빠르게

가입·로그인 없이 바로 시작. 모든 정보는 **내 기기에만** 저장됩니다. 나중에 상대방과 같이 쓰고 싶어지면 백업을 만든 뒤 같이 쓰는 저장소로 옮길 수 있습니다.

→ 배포 주소가 생기면 여기에 연결하세요. 로컬에서도 바로 시작할 수 있습니다.

장점: 가입 불필요 · 빠른 시작 · 로컬 저장
단점: 여러 기기 동시 편집과 RSVP는 같이 쓰기로 전환한 뒤 가능

### 🌐 3) 내 Supabase로 같이 시작 — 독립 운영

Supabase + Vercel을 연결해 우리 부부가 각자 폰에서 같은 데이터를 보고 편집합니다.

장점: 부부 동시 편집 · 청첩장 링크 공유 · 하객 RSVP
단점: 약 15분짜리 셋업 가이드 필요

앱 안에서 한 단계씩 안내합니다. 로컬에서 시작한 데이터도 전환 전에 백업하고, 사진을 두 기기에서 볼 수 있는 형태로 바꾼 뒤 저장합니다.

### 💻 4) 코드 받아 마음대로 고치기 — AI에게 시켜서

레포를 통째로 받아서 Claude Code, Cursor 같은 AI 도구에 던지면 **내 결혼식 식대로** 손볼 수 있어요. 색깔·디자인·기능 전부 자유.

```bash
git clone https://github.com/commet/wedding-os.git
cd wedding-os
npm install
npm run dev
```

이후 `CLAUDE.md` 또는 `AGENTS.md` 를 AI 도구에 함께 던지세요.

## AI 사용 방식

기본은 **Wedding OS AI**입니다. 운영자가 배포 환경변수에 Anthropic 키를 연결하면 사용자는 별도 키 없이 앱 안에서 바로 실행할 수 있습니다.

키를 연결하지 않은 배포나 로컬 개발 환경에서는 **챗봇 다리 모드**를 사용할 수 있습니다:
1. 도구가 ChatGPT/Claude/Gemini에 그대로 붙여넣을 프롬프트를 자동 생성
2. 사용자가 챗봇에 복붙
3. 답변을 도구에 다시 붙여넣으면 자동 반영

원하면 [AI 연결]에서 본인 Gemini/OpenAI/Claude/Ollama 설정으로 바꿔 쓸 수 있습니다.

## 데이터는 누구의 손에?

- 간편 시작: **운영자 Supabase의 암호문**. 복호화 키는 링크의 `#` 뒤에만 있고 서버로 전송되지 않음.
- 혼자 시작: **당신의 브라우저 저장소**. 본인 외엔 아무도 접근 못 함.
- 내 Supabase로 같이 시작: **당신의 Supabase 프로젝트**. 부부가 같은 저장소를 사용.
- 간편 발행: 청첩장 본문은 암호화되어 저장되고, 복호화 키는 공유 링크의 `#` 뒤에만 있음.
- 코드 직접 운영: **당신이 직접 호스팅하는 어디든**.

기본 설계 원칙은 운영자가 결혼 준비 데이터의 내용을 읽지 못하게 하는 것입니다. 단, 간편 발행의 카톡 미리보기용 이름·날짜처럼 링크 미리보기에 필요한 최소 메타는 평문으로 저장될 수 있습니다.

## 배포 환경변수

- `BLOB_READ_WRITE_TOKEN`: 간편 청첩장 발행, `/i/<code>` 공유 링크, 암호화 RSVP 저장에 필요합니다.
- `ANTHROPIC_API_KEY`: Wedding OS AI 기본 실행에 필요합니다. 서버 함수에서만 사용되며 클라이언트 번들에 들어가지 않습니다.
- `ANTHROPIC_MODEL`: 선택. 기본값은 `claude-3-5-haiku-20241022`입니다. 필요하면 Sonnet 계열 등으로 바꿀 수 있습니다.
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`: 같이 쓰는 저장소 기본 연결과 공개 청첩장 fallback에 필요합니다.
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`: 서버 함수에서만 쓰고 싶을 때 선택적으로 사용할 수 있습니다. 클라이언트 번들에는 `VITE_` 값만 들어갑니다.

`service_role` 키는 앱이나 Vercel 환경변수에 넣지 마세요.

## 🔒 보안 안내 (꼭 읽어주세요)

### 같이 쓰는 저장소는 owner token 기반으로 보호됩니다
전체 준비 데이터의 읽기·수정은 로컬 기기에 저장된 owner token 또는 직접 공유한 편집 링크가 있어야 가능합니다. 공개 청첩장 링크는 청첩장 본문과 RSVP 제출만 열립니다.
→ 다만 Supabase Auth 기반 계정 시스템은 아직 없으므로, 편집 링크는 **신랑·신부처럼 같이 관리할 사람에게만** 공유하세요.

### 데이터·시크릿 처리 원칙
- **AI 키**: 본인 기기에만 별도 저장. 백업 파일과 같이 쓰는 저장소 동기화에 포함되지 않음.
- **Supabase anon key**: 셋업 위저드의 호스트 검증을 통과한 공식 도메인만 허용. 백업 파일 다운로드 시 자동으로 제외.
- **외부 사람 백업 import**: 시크릿(연결 정보·AI 키)은 현재 기기 값을 유지 — 악의적 백업 파일이 연결을 바꿔치지 못함.
- **모든 외부 링크**: `noopener noreferrer` 적용. CSP·X-Frame-Options 등 보안 헤더 적용.
- **사용자 입력 URL/이미지**: `javascript:` 등 위험 스킴 차단.
